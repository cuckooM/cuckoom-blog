### 1. 当前问题分析

#### 1.1 样式文件结构分析

**当前主题样式架构**:
- `_design-system.styl` - CSS变量定义系统
- `_variables.styl` - 传统Stylus变量
- `_partial/mobile.styl` - 移动端导航样式（仅24行，非常简陋）
- `_components/_card.styl` - 文章卡片组件
- `_components/_hero.styl` - Hero区域组件
- `_partial/header.styl` - Header导航样式
- `_partial/article.styl` - 文章正文样式
- `_components/_sidebar-drawer.styl` - 侧栏抽屉组件
- `_partial/archive.styl` - 归档时间线样式
- `custom/pages.styl` - 分类/标签页面样式

**当前断点定义问题**:
```
// _variables.styl 定义的断点
mq-mobile = "screen and (max-width: 479px)"    // ❌ 过窄，遗漏480-767px区间
mq-tablet = "screen and (min-width: 480px) and (max-width: 767px)"
mq-normal = "screen and (min-width: 768px)"

// 实际使用的断点（不一致）
@media screen and (max-width: 767px)   // ✓ 正确覆盖移动端
@media screen and (max-width: 479px)   // ❌ 过窄
@media screen and (min-width: 768px) and (max-width: 1023px)  // ✓ 平板
@media screen and (min-width: 1024px)  // ✓ 桌面端
```

**问题**: `_variables.styl` 中的 `mq-mobile` 定义为 `max-width: 479px`，但实际组件中使用 `max-width: 767px`，导致断点不一致。

#### 1.2 具体问题清单

| 组件 | 问题类型 | 问题描述 | 严重程度 |
|-----|---------|---------|---------|
| **Header** | 定位遮挡 | Header固定定位(60px)，但Hero padding-top计算正确 | 低风险 |
| **移动端导航** | 功能缺失 | mobile.styl仅定义基础样式，缺少展开动画、遮罩、完整交互 | 高风险 |
| **文章卡片** | 标签溢出 | 标签容器使用flex+wrap，但超小屏(320px)可能出现挤压 | 中风险 |
| **文章正文** | 图片/表格 | 已有max-width:100%，但表格缺少横向滚动支持 | 中风险 |
| **侧栏抽屉** | 移动端适配 | 移动端已设width:100%，但关闭按钮点击区域需验证 | 低风险 |
| **分页组件** | 显示策略 | 已隐藏页码只显示当前，但按钮尺寸不足44px | 中风险 |
| **分类网格** | 响应式 | 已设置移动端单列，但间距可能过小 | 低风险 |
| **归档时间线** | 缩进适配 | padding-left:24px在超小屏可能占用过多空间 | 低风险 |
| **搜索展开框** | 定位问题 | 已设fixed定位，但需验证高度计算 | 低风险 |

#### 1.3 关键发现

**移动端导航核心问题**:
- `mobile-nav.ejs` 仅输出导航链接，没有汉堡菜单的展开/收起容器
- `mobile.styl` 定位 `#mobile-nav` 为 `absolute, top:0, left:0, width:280px`
- **缺失**: 没有遮罩层(overlay)、没有展开动画、没有关闭按钮
- Header中的 `mobile-menu-toggle` 按钮存在，但没有对应的JS交互逻辑

**代码分析**:
```stylus
// mobile.styl - 当前实现非常简陋
@media mq-mobile  // max-width: 479px - 断点有问题
  #mobile-nav
    position: absolute
    top: 0
    left: 0
    width: mobile-nav-width  // 280px
    // 缺少: 动画、遮罩、关闭逻辑
```

### 2. 响应式设计方案

#### 2.1 设计理念

**采用"渐进增强"策略**:
- 以移动端(375px)为基准设计
- 向上扩展适配平板和桌面端
- 保持设计系统一致性(8px网格)

**核心原则**:
1. 内容优先 - 移动端只显示核心内容，次要信息隐藏或简化
2. 触控友好 - 所有可点击元素最小44px×44px (Apple标准)
3. 横向滚动隔离 - 代码块/表格横向滚动不影响整体页面
4. 视觉一致性 - 保持设计系统变量在所有断点生效

#### 2.2 移动端导航重构方案

**方案A: 侧边栏抽屉式导航** (推荐)

```
交互流程:
┌─────────────────┐
│ [☰] Logo [🌙]  │ ← Header (60px固定)
├─────────────────┤
│                 │
│   主内容区域    │
│                 │
└─────────────────┘

点击[☰] → 从左侧滑入导航抽屉 + 半透明遮罩

┌─────────────────┐
│ [X] 导航菜单    │ ← 抽屉Header
├─────────────────┤
│ 首页            │
│ 归档            │
│ 分类            │
│ 标签            │
│ 关于            │
├─────────────────┤
│ 语言切换        │ ← 底部功能区
└─────────────────┤
      ↓
  半透明遮罩覆盖主内容
```

**视觉规格**:
- 抽屉宽度: 280px (占屏幕75%，预留25%遮罩可见)
- 抽屉背景: `var(--color-card-bg)`
- 遮罩背景: `rgba(0, 0, 0, 0.3)`
- 滑入动画: `transform: translateX(-280px)` → `translateX(0)`，200ms ease-out
- 导航项高度: 48px (满足44px触控标准)
- 关闭按钮: 右上角，尺寸44px×44px

#### 2.3 文章卡片移动端优化方案

**布局调整**:
```
桌面端:
┌──────────────────────────────────────────┐
│ 标题                                [日期]│
│ 摘要文字摘要文字摘要文字摘要文字摘要文字...│
│ [标签1] [标签2] [标签3]           [阅读更多]│
└──────────────────────────────────────────┘

移动端(紧凑布局):
┌──────────────────────┐
│ 标题                 │
│ 日期 · 分类          │
│ 摘要文字摘要文字...  │
│ [标签1][标签2][标签3]│
│            [阅读更多]│
└──────────────────────┘

超小屏(320px):
┌────────────────────┐
│ 标题               │
│ 日期               │
│ 摘要文字摘要...    │
│ [标签1][标签2]...  │ ← 标签可能需折叠或滚动
│         [阅读更多] │
└────────────────────┘
```

**视觉规格**:
- 卡片内边距: 16px (从24px减少)
- 标题字号: 保持20px，但可能截断超长标题(2行)
- 标签间距: 6px → 4px
- 标签字号: 12px (从13px减少)
- 阅读更多按钮: 最小宽度80px，满足触控

#### 2.4 文章正文移动端优化方案

**阅读体验优化**:
- 正文宽度: `calc(100vw - 32px)` (两侧各16px边距)
- 字号: 保持16px，行高1.6em
- 标题层级: h2=22px, h3=18px, h4=16px (从桌面端缩小)
- 图片: `max-width: 100%` + 居中显示
- 代码块: `overflow-x: auto` + 横向滚动提示箭头
- 表格: 容器包裹 + `overflow-x: auto`

**表格横向滚动方案**:
```
┌──────────────────────┐
│ 表格容器(横向滚动)   │
│ ←──────────────────→ │ ← 滚动指示
│ | Header | Header |  │
│ | Data   | Data   |  │
└──────────────────────┘
```

#### 2.5 Hero区域移动端适配方案

**高度计算**:
- 移动端: `min-height: 80px, max-height: 120px`
- 标题字号: 26px (从32px减少)
- 副标题字号: 16px (从18px减少)
- 内边距: 上下24px，左右16px

**与Header的配合**:
- Hero `padding-top: calc(var(--header-height) + 24px)` = 84px
- Header固定在顶部，不遮挡Hero内容

#### 2.6 分页组件简化方案

**移动端分页显示**:
```
桌面端:
[上一页] [1] [2] [3] ... [10] [下一页]

移动端:
[上一页] 3/10 [下一页]
          ↑
      当前页码/总数
```

**按钮规格**:
- 上一页/下一页按钮: 最小宽度44px，高度36px
- 页码显示: 简化为"当前页/总页数"格式

#### 2.7 归档时间线适配方案

**缩进调整**:
```
桌面端:
2024
  └─ 01月
      ├─ 01-15 文章标题 [标签]
      └─ 01-20 文章标题 [标签]

移动端:
2024
├─ 01月
│   ├─ 01-15 文章标题
│   └─ 01-20 文章标题
```

**规格**:
- 年份缩进: 0px (左对齐)
- 月份缩进: 16px (从24px减少)
- 文章缩进: 24px (层级清晰)
- 时间线边框: 2px宽度，颜色 `var(--color-border)`
- 标签: 超小屏可隐藏或折叠

### 3. 断点定义

#### 3.1 新断点体系

**统一断点变量** (建议替换 `_variables.styl`):

```stylus
// 响应式断点 - 统一标准
$breakpoint-xs = 320px   // 超小屏手机 (iPhone SE 等)
$breakpoint-sm = 375px   // 小屏手机 (iPhone 6/7/8, iPhone X)
$breakpoint-md = 768px   // 平板/大屏手机分界点
$breakpoint-lg = 1024px  // 桌面端分界点
$breakpoint-xl = 1280px  // 大屏桌面端

// 媒体查询定义
mq-xs = "screen and (max-width: 374px)"        // 超小屏 (≤374px)
mq-mobile = "screen and (max-width: 767px)"    // 移动端统一 (≤767px)
mq-tablet = "screen and (min-width: 768px) and (max-width: 1023px)"  // 平板
mq-desktop = "screen and (min-width: 1024px)"  // 桌面端
```

#### 3.2 断点对应设备

| 断点 | 宽度范围 | 代表设备 | 布局策略 |
|-----|---------|---------|---------|
| xs | ≤374px | iPhone SE, 小屏Android | 单列，极致精简 |
| mobile | ≤767px | iPhone 12/13/14, Galaxy S系列 | 单列，紧凑布局 |
| tablet | 768-1023px | iPad Mini, iPad, 大屏手机 | 双列(可选)，适中布局 |
| desktop | ≥1024px | MacBook, Desktop | 多列，完整布局 |

#### 3.3 组件断点映射

| 组件 | xs | mobile | tablet | desktop |
|-----|----|----|----|----|
| Header | 固定60px | 固定60px | 固定60px | 固定60px |
| 移动导航 | 全宽抽屉 | 280px抽屉 | 隐藏(用桌面导航) | 隐藏 |
| 文章卡片 | 内边距12px | 内边距16px | 内边距20px | 内边距24px |
| 分类网格 | 1列 | 1列 | 2列 | 2列 |
| 标签网格 | 2列 | 2列 | 3列 | 3列 |
| 分页 | 简化 | 简化 | 简化 | 完整 |
| Hero高度 | 80-100px | 80-120px | 100-140px | 100-160px |

### 7. 验收标准补充

- [ ] 汉堡菜单点击响应≤100ms
