# 多语言重构需求

## 背景

当前博客项目使用硬编码路径方式支持中英文双语：
- 判断语言：`page.path.startsWith('en/')`
- URL 转换：手动处理 `/tags/ → /en/tags/`
- Generator：7个自定义 generator（en_tag_generator 等）

## 问题

1. **无法扩展**：硬编码只支持英文，无法支持日语、韩语等其他语言
2. **维护成本高**：22个模板文件使用硬编码路径判断
3. **不标准**：不符合 Hexo 官方 i18n 最佳实践

## 目标

重构为基于 `page.lang` 的标准多语言方案，支持任意语言扩展。

## 需求细节

### 技术需求

1. **Helper 重构**：
   - 改用 `page.lang` 属性判断语言（默认 'zh-CN'）
   - 动态生成语言前缀（en → /en, jp → /jp）
   - 提供通用 helper 支持任意语言

2. **Generator 优化**：
   - 合并 7 个自定义 generator 为通用版本
   - 生成的页面对象包含 `lang` 属性
   - 根据 `_config.yml` 语言配置动态生成

3. **模板修改**：
   - 22个模板文件改用新的 helper
   - 移除硬编码路径判断
   - 使用 `page.lang` 或 `get_current_lang()` helper

4. **配置标准化**：
   - 在 `_config.yml` 定义支持的语言列表
   - 新增语言只需添加配置，无需修改代码

### 验收标准

1. ✓ 构建成功（无语法错误）
2. ✓ 中文环境链接正确（/categories/Java/）
3. ✓ 英文环境链接正确（/en/categories/Java/）
4. ✓ 标签、分类、归档数量按语言统计正确
5. ✓ 架构支持任意语言扩展（添加配置即可）

### 约束

- **本地验证**：代码不提交 git 远端，只在本地验证
- **渐进式重构**：分阶段实施，每阶段独立验证
- **保持功能**：重构过程中不破坏现有功能

### 未来语言支持

计划支持：
- zh-CN（中文，默认）
- en（英文，已支持）
- jp（日语，计划）
- ko（韩语，计划）
